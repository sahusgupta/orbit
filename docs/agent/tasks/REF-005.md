# REF-005: Extract operational demand, table, analytics, and participant rules

Status: `complete`

Date: 2026-08-07

## Objective

Move the remaining renderer-owned demand, table/session projection, operational analytics, participant selection, outreach script, and opportunity rules from `src/main.tsx` into focused domain modules without changing calculations, identity matching, scoring, ordering, text, or input state.

## In scope

- demand counts, viability, running/open session selection, table health, overflow, and closest-game labels;
- player/session hours, buy-in identity matching, average stack, and seat hours;
- operational and usage analytics plus the existing analytical-report payload projection;
- participant pool and likely-participant scoring, reasons, identity, limits, and type guards;
- staff script interpolation/selection and operational opportunity ordering.

Table/waitlist mutations, renderer state orchestration, API/report submission, persisted shapes, scoring redesign, identity-policy redesign, UI extraction, and styling remain out of scope.

## Characterization

Before relocation, `src/domain/operations.test.ts` imports the unchanged implementation through temporary named test exports. Its three dense cases pin:

- exact demand accounting, viability/health/overflow labels, scripts, session matching, hours, buy-ins, average stacks, and seat hours;
- participant availability scoring, profile-derived adjustments, stable ordering, reasons/messages, active-player exclusion, type guards, limits, and immutability;
- operational/usage analytics, financial estimates, time windows, aggregation ordering, analytical payload rounding/shapes, opportunity ordering, and immutability.

The existing table-planning, planned-participant, waitlist, lifecycle, transition, and result-builder suites remain the mutation-side characterization. The new pre-change focused command passed 1 file/3 tests, and both root TypeScript projects passed with zero diagnostics.

## Acceptance criteria

- The three direct cases and existing mutation suites remain exact after importing focused domain modules.
- `src/main.tsx` no longer owns these projection/scoring/aggregation implementations or temporary test exports.
- No calculation, identity rule, score, order, string, payload, or persisted/public contract changes.
- Focused tests and `npm run verify` pass.

- Added `src/domain/participants.ts` for active/inactive interest constants, profile resolution, in-club selection, participant scoring, likely-player outreach, and candidate type guards.
- Replaced the implementations, shared constants/types, and temporary exports in `src/main.tsx` with direct imports; all mutations and renderer orchestration remain in the entrypoint.
