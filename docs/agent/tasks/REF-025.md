# REF-025: Split and validate Player data adapters

Status: `complete`

Date: 2026-08-10

## Objective

Replace the 1,328-line mixed Player data adapter with focused authenticated HTTP, Firebase Auth, Firestore repository, subscription, decoder, and legacy-compatibility owners while preserving the `orbitSyncApi.ts` public facade, paths, queries, request bodies, revision selection, source ordering, identity rules, fallback behavior, and user-visible errors.

## Characterization and isolation gate

REF-024 supplied the required unchanged-production fake-only gate: 3 files / 44 tests covering HTTP/Auth, Firestore reads and writes, local/remote/published/legacy snapshot sources, protocol revisions, malformed records, ordering, deduplication, timers, listeners, and teardown. It passed before the first migration and after every adapter migration. Firebase App/Auth/Firestore and `fetch` remained in-memory fakes; no SDK connection, socket, hosted endpoint, credential, production record, or tracked database was accessed.

The final boundary added four direct decoder cases, taking the focused characterization/decoder gate to 4 files / 48 tests. The broader Player data/domain gate passes 9 files / 73 tests.

## Preserved behavior

- Hosted and local URLs, methods, bearer/content headers, query parameters, JSON request bodies, and account-deletion order are unchanged.
- Membership and waitlist submission still tries hosted HTTP, then the configured loopback bridge, then writes both current and legacy Firestore request paths before reading or updating the existing snapshot fallback.
- Protocol-v2 parent/child revision selection, future-child rejection, expected child counts, source freshness/merge ordering, player scoping, visibility filters, polling cadence, listener replacement, late-result suppression, and teardown are unchanged.
- Auth sign-in-first/create-second behavior, existing-email error selection, verified-claim refresh, phone mapping, profile identity override, tournament privacy/gates, private-game ordering, and all characterized failure strings are unchanged.
- REF-024's non-uniform legacy policies remain explicit: malformed profiles pass through unchanged, null tournament events project to document/club IDs, and null private-game records still fail/throw at their characterized boundaries.
- HTTP identity, checkout, and snapshot payloads now enter as `unknown` and must satisfy their required structures before becoming canonical results. Error fields and Firebase error codes are read without boundary assertions.
- No Firestore/API path, collection, document, payload schema, persisted shape, public facade export, authentication policy, or dependency changed.

## Player-web readiness

`playerIdentity.ts` and `playerBoundaryDecoders.ts` are newly reusable without React Native, Expo, storage, purchase, or Firebase runtime imports. Existing canonical contracts and pure discovery/protocol helpers remain reusable. The focused API/Firebase/subscription modules can now be selected or replaced independently by a future web composition instead of importing a monolith.

`player-app/src/domain/decoders/playerGameDecoder.ts` and `player-app/src/domain/playerSnapshotTransforms.ts` still use Firestore document types, and application hooks still import the concrete facade. Those are explicit adaptation seams, not claims of transport independence. Native presentation, maps, Expo services, AsyncStorage, and RevenueCat remain platform-specific. REF-025 did not design or build a Player website.
