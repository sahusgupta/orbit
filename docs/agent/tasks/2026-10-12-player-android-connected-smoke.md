Strict preflight requires the booted dedicated emulator, airplane on, Wi-Fi/mobile off, no IPv4 routes or IPv6 default, DOWN interfaces and no active default network. The native network policy permits cleartext only to `127.0.0.1`; it does not restrict ports, so the runtime reverse-list guard remains necessary. Package/PID filtering happens inside the guest before diagnostic logs reach the host. Tokens, credentials, profile payloads and physical coordinates are forbidden diagnostic fields.

Prepared scenarios cover actual email/password UI sign-in, remote profile/discovery, API Save/Undo/preferences, independent SDK peer/native `onSnapshot`, stale-draft reload, API outage with real durable pending journal/cold restoration/retry, idempotent receipt replay and owner B isolation. It preserves unrelated PLO and A private state. The canonical publication outbox is **not** drained; this is authoritative local API→native polling, not management publication or a pilot.
