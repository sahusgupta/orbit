## Confirmed defect and scope

The authenticated Match persistence port returns a Firestore `onSnapshot` subscription. Its error callback is terminal: [Firebase documents that no further events arrive after a listener error](https://firebase.google.com/docs/firestore/query-data/listen#handle_listen_errors). The installed SDK's declaration independently states the same contract. The repository forwards this error to the controller, which displays it but retains its unsubscribe handle. `retry()` successfully fetches and persists the current state, then `startListener()` sees that old handle and skips a replacement subscription. The mounted same-owner hook is not recreated, so later cross-device saves and preferences stop updating even though Retry appears successful. A synchronous subscription error returning a no-op handle has the same problem.

The intended small change is to retire failed subscriptions and let an explicit successful Retry install exactly one replacement. Healthy retries must retain the existing subscription, failed refetches must not start one, and callbacks from retired subscriptions must not alter current state or errors. Disposal, durable journal ordering, preference conflict reconciliation, mutation identities, API/auth/security rules and persisted shapes must remain intact. There is no automatic retry loop or provider-policy change. A separate [card reader summary correction](./2026-10-15-player-card-reader-summary.md) addresses visible primary facts missing from the hero's accessible name without changing the visual layout.
