# REF-024: Characterize Player external-data and subscription boundaries

Status: `complete`

Date: 2026-08-09

## Objective

Pin the current authenticated HTTP, Firebase Auth, Firestore read/write, published/legacy snapshot, sync-protocol, and subscription behavior of `player-app/src/data/orbitSyncApi.ts` before REF-025 separates or validates that adapter. This task changes tests and evidence only.

## Isolation gate

The pre-task direct boundary was 2 files / 7 tests: six sync-protocol cases and one published-game normalization case.

`player-app/src/data/orbitSyncApi.boundary.test.ts` installs hoisted in-memory fakes for every imported Firebase App/Auth/Firestore function plus global `fetch`. References are represented as inert path objects; documents, queries, listeners, unsubscriber calls, server timestamps, transactions, timers, auth users, and HTTP responses are controlled entirely inside the test process. One local-bridge case dynamically reloads the adapter with an explicit loopback URL, but `fetch` remains the fake. No SDK, loopback socket, hosted API, credential, or production record is contacted.

## Characterized behavior

### Authenticated HTTP and Auth

- Identity status, identity session, membership checkout, account deletion, remote snapshot, membership request, and waitlist request URLs, methods, bearer headers, JSON bodies, success shapes, error payloads, malformed JSON/payloads, missing sign-in, and fetch failure.
- Verified identity responses force a refreshed Firebase token after the authenticated request.
- Account deletion completes remote identity cleanup before deleting the Firestore profile and Firebase user; remote failure prevents both local deletions.
- Email normalization, sign-in-first/create-second behavior, preservation of the original sign-in error for an already-existing email, password/email/phone validation, phone-to-internal-email mapping, current-user projection, auth listener null/user mapping, and sign-out delegation.
- Request submission keeps the current remote → configured local bridge → dual Firestore request path → published/legacy snapshot fallback order.

### Firestore records and compatibility

- Profile write identity override, membership-map merge, server timestamp, valid/missing/read-failure behavior, and the current unvalidated malformed-profile passthrough.
- Private-game open-only filtering, newest-first ordering, empty reads, malformed null-record failure result, write timestamp/options, and read/write errors.
- Tournament visible-club filtering, event document-ID/club-ID projection, same-user registration queries, identity-mismatch privacy behavior, missing/malformed events, read failure, registration identity/time gates, write shape, self-unregistration gates, and delete path.
- Protocol-v2 club hydration, expected child-count validation before player-visible filtering, per-player membership/waitlist/notification filtering, hidden club/game exclusion, external-record immutability, and future-child hold behavior.
- Configured/missing/malformed/failed local bridge behavior; authenticated remote duplicate merging; freshest snapshot selection; visible legacy `clubStates` fallback; empty legacy results; and malformed/failed legacy reads.
- Published-game numeric fallbacks, v2 aggregate ordering, legacy live-session exclusion beside versioned aggregates, empty input, immutable external values, and the current null-record throw.

### Revisions and subscriptions

- Legacy compatibility, partial-v2 rejection, parent/child revision selection, server-managed unversioned records, ordering, input immutability, numeric-string/missing/invalid/negative entity-count handling, and malformed/missing publication timestamps.
- Private-game success/error/malformed listener behavior and direct unsubscriber ownership.
- Tournament root/child listener replacement, visible-club selection, registration privacy, late-result suppression, and complete teardown.
- Live-club child-listener deduplication, current-revision emission, future-revision suppression, cached-data behavior after root errors, removed-club detachment, malformed-child behavior, concurrent-refresh deduplication, one restartable polling timer, and full teardown.

## Current malformed-record policy captured for REF-025

The unchanged adapter does not apply one uniform decoder policy today:

- malformed profile documents are returned through the asserted profile type unchanged;
- a null private-game document becomes an `{ ok: false }` read result;
- a null published-game document throws from normalization;
- a null tournament event is projected as an object containing only document and club IDs;
- invalid or absent v2 expected-game counts do not block a revision, while a numeric string is accepted through number coercion;
- future-child detection requires parseable parent and child timestamps once a committed parent revision exists.

These are characterization facts, not endorsements. REF-025 may add runtime validation only while preserving the accepted valid/legacy contracts and explicitly accounting for these malformed cases.
