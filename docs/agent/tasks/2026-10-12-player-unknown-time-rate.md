Actual native connected QA exposed a client compatibility bug: the verified player profile and private Match state restored successfully, but the game feed was empty. The authoritative API and management projection intentionally omit `timeAccess.hourlyFeeCents` when a Time venue has not authored its rate. Management's `PlayerTimeAccess` already types that field as optional. The player decoder required it, rejected the entire authenticated venue, and returned a successful discovery envelope containing no decoded clubs. Public discovery omits private time-access data and therefore retained the same venue. Pure characterization reproduced two published games/tables, zero authenticated decoded clubs and one public decoded club; this was not a missing license or a Match filter problem.

The narrow fix aligns the existing [player type](../../../player-app/src/domain/playerSync.ts) and [decoder](../../../player-app/src/domain/decoders/playerBoundaryDecoders.ts) with the established optional field. An absent rate is accepted without adding a value. Present null, negative, nonfinite, string, object and boolean values still reject the venue. Required enabled/linked/saved-minute/session validation remains intact. The [rate helper](../../../player-app/src/domain/clubAccess.ts) narrows the optional number and preserves `Time rate not published`; an explicitly published zero remains `$0.00/hr`. No API, publisher, authentication, payment, persistent shape, fixture price or backend deployment changed.
