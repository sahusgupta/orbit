# REF-014: Extract management seating and player-session commands

Status: `complete`

Date: 2026-08-08

## Objective

Move seating, moves, player-session corrections and departure, time/buy-in accounting, collection-mode propagation, and drop/dealer/hand writes out of `src/main.tsx` into pure application commands without changing identity, ordering, timers, audit records, financial shapes, notifications, or persistence behavior.

## Characterization

Before production edits, the existing player-transition, table-lifecycle, and event-reporting suites passed 3 files / 23 tests. The transition and lifecycle matrices already covered authoritative profile IDs, unique-name fallback, ambiguous-name no-mutation, moves, departures, table events, seat counts, correction logs, ordering, immutability, usage events, and persistence.

Four missing renderer cases were added against unchanged production and committed separately as `81dc007`:

- successful initial seating with purchased time, initial buy-in, check-in/buy-in ledger order, interest conversion, table start/count, and profile frequency;
- exact missing-table, missing-player, duplicate-player, and occupied-seat failures;
- elapsed-time player-time accounting, buy-ins, and collection-mode propagation;
- drop, dealer, and hand-log trimming, ordering, replacement, and persistence.

The expanded unchanged-production boundary passed 3 files / 27 tests before extraction.

## Implementation

- Added `src/application/management/seatingCommands.ts` for seat availability/count projection, canonical seating, initial accounting, profile frequency, and cross-table moves.
- Added `src/application/management/playerSessionCommands.ts` for audited session corrections, seat validation, collection mode, player time, buy-ins, drop/dealer/hand writes, interest departure, and cash-out/profile accounting.
- Injected ID, ISO-clock, and elapsed-time clock dependencies. Neither module imports React, browser, Electron, Firebase, or storage APIs.
- Kept draft parsing, dialogs, usage descriptors, notification fan-out, persistence, and UI state in `App`.
- Preserved authoritative profile-ID behavior and the existing unique-name fallback, record order, status/timestamp/manual-edit semantics, seat-count synchronization, correction-log cap, financial/ledger shapes, time-fee math, and notification triggers.
- Added 13 direct command cases. The renderer matrices remain as orchestration/persistence characterization while the direct suites own the pure transitions.

`src/main.tsx` decreased from 5,353 to 4,991 lines. Its `App` function decreased from 4,738 to 4,370 lines. The focused production modules are 318 and 391 lines and contain no explicit `any`.
