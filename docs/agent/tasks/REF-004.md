# REF-004: Extract licensing and staff authentication helpers

Status: `complete`

Date: 2026-08-07

## Objective

Move renderer licensing/account-identity helpers and staff-secret hashing/verification from `src/main.tsx` into focused modules without changing cryptography, compatibility, storage partitioning, license validation, access dates, or error semantics.

## In scope

- PBKDF2-SHA256 staff/account secret derivation and legacy salted SHA-256 verification;
- pilot-access date checks and normalized account-key selection;
- per-account management/auth storage keys and persisted sign-in records;
- P-256 public-key/signature decoding and verification;
- signed pilot-key field aliases, validation order, and normalized `PilotAccess` construction.

Firebase authentication, Electron/API license validation, login UI/orchestration, account creation, persisted management-state shapes, credential migration policy, and cryptographic redesign remain out of scope.

## Characterization

Before relocation, `src/lib/pilotSignature.test.ts` exercises the unchanged implementation through its existing in-memory cryptographic harness plus a temporary named test seam. Eight cases pin:

- valid raw/DER P-256 signatures, wrong keys, modified payloads, malformed signatures, and unsupported keys;
- the exact `pbkdf2-sha256$210000$<hex>` output, modern verification, legacy salted SHA-256 compatibility, and rejection;
- date-only expiration semantics, access authorization, account-key priority/sanitization, storage-key shapes, persisted sign-in matching/removal, and saved timestamp;
- valid signed-key normalization plus unsigned, short-code, invalid-date, and expired-key error precedence.

The pre-change focused command passed 1 file/8 tests, and both root TypeScript projects passed with zero diagnostics.

## Acceptance criteria

- The eight direct cases remain exact after importing focused licensing and staff-auth modules.
- `src/main.tsx` no longer owns cryptographic, account-key, persisted-sign-in, signature, or key-file validation implementations or the temporary test exports.
- Existing login/account orchestration and all persisted/auth/public contracts remain unchanged.
- Focused tests and `npm run verify` pass.

## Implementation and verification

- Added `src/domain/staffAuth.ts` as the owner of exact PBKDF2 derivation and legacy salted SHA-256 verification.
- Added `src/domain/licensing.ts` as the owner of the canonical management storage prefix, access/date/account-key helpers, persisted sign-in handling, P-256 signature conversion/verification, and pilot-key validation.
- Replaced the implementations and temporary exports in `src/main.tsx` with direct imports; UI, Firebase authentication, and account orchestration remain in the entrypoint.
- Rewired `src/lib/pilotSignature.test.ts` to import the focused modules directly, removing the Node inspector, React mount, desktop bridge, Firebase, and fetch harness while preserving all eight cases.
- Focused licensing/account coverage passed 2 files/17 tests; both root compiler projects passed with zero diagnostics; Player TypeScript, all 36 files/195 tests, the 1,917-module renderer build, and `npm run verify` passed.
- `src/main.tsx` decreased from 9,072 to 8,918 lines. No cryptographic parameter, legacy compatibility path, storage key, persisted shape, license rule, external service, or deployment changed.
