# REF-002: Extract state defaults and persisted-state normalization

Status: `complete`

Date: 2026-08-07

## Objective

Move management state defaults, seed construction, and persisted-state parsing/normalization from `src/main.tsx` into a focused renderer-domain module without changing persisted shapes, legacy mappings, record ordering, or fallback behavior.

## In scope

- default membership/script/tournament fixtures used by state construction;
- ID/date helpers required by those defaults and still consumed by `main.tsx`;
- table-cap and proven legacy collection/status normalization;
- `seedState`, `normalizeState`, and `parsePersistedAppState`;
- type-only import and call-site rewiring.

Browser storage selection, desktop/Firebase publication, account-restore orchestration, UI state, and behavior redesign remain out of scope.

## Characterization

The existing account-restore suite already covered null/bridge/local fallbacks, current persisted records, historical/current/corrupt collection modes, malformed JSON, and persistence after restore. Before production relocation, a ninth case was added against unchanged behavior to pin:

- legacy game/status/collection representations;
- profile generation and date/game defaults;
- active-seat collision repair and record order;
- tournament, table-event, notification, membership-plan, and account-login defaults;
- loaded-record immutability.

The focused pre-change command passed 1 file/9 tests.

## Acceptance criteria

- The characterized results remain exact after relocation.
- `src/main.tsx` no longer owns state default/normalization implementations.
- No persistence, API, Firebase, Electron, or Player payload changes occur.
- Focused tests and `npm run verify` pass.

## Completed implementation

`src/domain/state.ts` now owns the existing default membership/script/tournament fixtures, date/ID helpers used by those defaults, table-cap and proven legacy mappings, seed state, normalization, and persisted-JSON parsing. `src/main.tsx` imports those functions and retains browser storage selection, restore orchestration, Desktop/Firebase publication, UI state, and all mutations.

The move preserves every characterized field, ordering rule, input-immutability rule, and safe fallback. No persisted, API, Firebase, Electron, or Player shape changed.

Final verification passed: both root compiler projects; the focused account-restore suite (1 file/9 tests); all renderer-mount characterization (15 files/77 tests); Player TypeScript; all 35 files/189 tests; the 1,914-module renderer build; and `npm run verify`.

`src/main.tsx` decreased from 9,751 to 9,364 lines; the extracted state module is 411 lines.
