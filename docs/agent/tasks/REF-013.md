# REF-013: Extract management waitlist commands

Status: `complete`

Date: 2026-08-08

## Objective

Move waitlist interest creation, patching, timestamp correction, removal, check-in ensuring, and demand-prompt decisions out of `src/main.tsx` into a pure application module without changing identity, ordering, timestamps, manual-edit tracking, correction logs, thresholds, or direct-seat behavior.

## Characterization

Before production edits, the existing waitlist update, state-correction, and quick-add suites passed 3 files / 20 tests. They already cover authoritative profile relationships, active and inactive transitions, timestamp/session mirroring, direct seating, ordering, demand thresholds, usage reporting, and persistence handoff. No uncovered production branch required a new renderer-level characterization commit.

The extracted owner adds 12 direct command cases covering all seven non-seated creation statuses, existing-identity replacement and order, the exact six-player prompt descriptor, inactive patches and manual edits, prompt suppression, timestamp/session corrections, audited missing-target no-ops, authoritative check-in relationships, removal, and input immutability.

## Implementation

- Added `src/application/management/waitlistCommands.ts` as the React- and platform-independent owner of canonical non-seated interest upserts, patches, corrections, removal, check-in ensuring, and demand-prompt descriptors.
- Reused the canonical active/inactive status sets from `src/domain/participants.ts`; the extraction does not introduce a second status policy.
- Injected ID and ISO-time creation so tests and callers control nondeterminism.
- Kept direct seating, browser prompts, table creation/switching, usage events, persistence, alerts, and confirmation dialogs in `App` for their later application/UI boundaries.
- Preserved the authoritative profile-ID plus unique-unlinked-name fallback, active-entry replacement, prepend/order behavior, exact timestamp call behavior, 50-entry correction-log cap, six-player demand threshold, open-table suppression, and persisted `Interest` shapes.

`src/main.tsx` decreased from 5,464 to 5,353 lines. Its `App` function decreased from 4,858 to 4,738 lines. The new focused production module is 260 lines and contains no explicit `any`.
