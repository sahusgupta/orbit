# REF-017: Extract tournament and night-close commands

Status: `complete`

Date: 2026-08-08

## Objective

Move tournament creation/settings/rerun, registration, seating draw, clock and level lifecycle, entries, payouts, check-in, elimination, and completion; plus night-close save/sign/lock/reopen, audit, history, and room-cleanup transitions out of `src/main.tsx` into pure application commands without changing identities, clocks, formulas, status mapping, ordering, validation text, signatures, locks, or persistence behavior.

## Characterization

Before production edits, the tournament-view, night-close calculation, and table-event reporting suites passed 3 files / 10 tests. They covered presentation, financial reconciliation and warning formulas, reporting order, and export behavior, but did not execute the mutation lifecycles.

Three unchanged-production lifecycle cases were added and committed separately as `c517ab9`:

- normalized tournament creation, settings edits, and rerun lifecycle reset;
- authoritative registration, check-in/start/pause/resume/level clock fields, rebuy/add-on, payout, and elimination/finish mapping;
- night-close save, staff sign-off, manager lock, operational cleanup/history/event creation, and manager reopen with exact audit order.

The expanded unchanged-production boundary passed 5 files / 13 tests before extraction.

## Implementation

- Added `src/application/management/tournamentCommands.ts` for tournament structure creation/update/rerun, deterministic injected table draws, registration, clock/status transitions, bounded levels, entries, payouts, check-in, elimination, and completion.
- Added `src/application/management/closeoutCommands.ts` for explicit save/sign/lock/reopen validation and transitions, staff/manager audits, warning cleanup, one-per-date history, and table/player/interest/event cleanup.
- Injected IDs, clocks, dates, and randomness. Neither module imports React, browser, Electron, Firebase, storage, or provider APIs, and neither contains explicit `any`.
- Kept forms, navigation, TV-window timing, dialogs/confirmation/prompts, calculated closeout inputs, usage descriptors, persistence, and route composition in `App`.
- Preserved source-vs-current tournament callback semantics, ID/clock call order, tournament status/finish mapping, payout normalization, membership-independent registration identity, reconciliation calculations, audit append order, signatures, lock/reopen fields, history idempotency, and close-event order.
- Added 8 direct command cases. Renderer lifecycle cases remain the orchestration/persistence boundary while direct suites own pure outcomes and validation failures.

`src/main.tsx` decreased from 4,446 to 4,351 lines. Its `App` function decreased from 3,804 to 3,692 lines. The focused tournament and closeout modules are 298 and 236 lines.
