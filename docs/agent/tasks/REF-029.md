## Dead-code decisions

The strict audit used the normal compiler gates plus `--noUnusedLocals --noUnusedParameters`, repository-wide symbol search, configured-entry review, and history for behavior-bearing candidates.

Removed:

- unused renderer/Player imports, destructures, aliases, constants, memoized projections, and component locals;
- unreachable management helpers for prior tournament formatting, correction wrapping, profile quick-fill, seat lookup aliases, and unused table projections;
- the already-unreachable undo callback after history confirmed its UI control was removed before this queue; the existing undo snapshot write cadence remains until product scope decides whether to restore or remove it;
- obsolete Player `toggleFavoriteClub` and `changeMembership` hook actions after current search found no consumer and history showed their earlier UI controls had been removed;
- unused Player hook return properties and their now-unused setter/provider imports;
- a no-op Player snapshot object spread and the domain-layer Firebase SDK type dependency.

The main dead-local checkpoint removed 123 lines while preserving public signatures. The later Player hook checkpoint removed another 51 lines. Final line counts are 3,514 for `src/main.tsx` and 953 for `player-app/src/PlayerApp.tsx`.

Retained deliberately:

- `updateInterestTimestamp` and `markPlayerLeft`, because renderer characterization invokes those named application closures directly even though current route markup does not render their former controls;
- `LocationStep`, `RadiusStep`, `GameStep`, and `StakesStep`, because the Player onboarding presentation contract deliberately fingerprints those dormant product steps;
- the write-only undo snapshot setter/cadence pending a product decision;
- the two design-system candidates and all configured/native/dynamic entrypoints.

The final strict-unused diagnostic set is exactly those two management closures and four Player onboarding steps. The ordinary strict project typechecks remain green. The full test gate caught both protected management closures before task completion; each was restored and reverified rather than deleting characterized behavior.

No `TODO`, `FIXME`, `HACK`, or temporary migration marker remains in production source or the audit script.

## Error-policy classification

No user-visible error message or fallback result changed. Silent paths fall into these existing policies:

| Policy | Examples | Preserved outcome |
| --- | --- | --- |
| Explicit failure | authentication, licensing, payment, request submission, provider/bootstrap, API/Firestore decoders | throw, structured error, status text, alert, or logged failure |
| Defensive parse/default | browser/device state, licensing payloads, QR/input parsing, optional API bodies | reject invalid input or return the documented empty/default value |
| Local-authoritative fan-out | localhost bridge, Firebase mirroring, telemetry, error reporting | local/browser/desktop state result remains authoritative; optional fan-out cannot block it |
| Best-effort hydrate/subscription | desktop/cloud startup, Player profile/tournament eager reads, pilot refresh | retain already usable local/default state and allow later subscription/refresh recovery |
| Compatibility acknowledgement | current and legacy Firebase request aliases | acknowledge aliases independently so one absent path does not block the other |
| Optional OS handoff | navigation URL and clipboard APIs | keep the existing attempted-action policy without inventing a new UI state |

Ambiguous best-effort call sites now state the policy adjacent to the catch. Clipboard success feedback and device/cloud persistence recovery remain possible UX improvements, but changing them requires a separately scoped error-policy decision.
