# REF-016: Extract profile and membership commands

Status: `complete`

Date: 2026-08-08

## Objective

Move profile construction, validation, edits, deletion, duplicate merges, club relationships, membership approval/activation, notification projection, and membership revenue out of `src/main.tsx` into pure identity-safe application commands without changing names, IDs, dates, relationship fallback, reference rewrites, revenue shapes, notification order, UI feedback, demand prompts, usage, or persistence behavior.

## Characterization

Before production edits, the profile-relationship, duplicate-grouping, and membership suites passed 3 files / 12 tests. Existing renderer coverage already pinned authoritative IDs, unique unlinked-name fallback, ambiguity refusal, no fallback from unresolved authoritative IDs, deletion, duplicate merges, reference order, club check-in/removal, and persistence.

Three missing unchanged-production money and membership cases were added and committed separately as `8406cba`:

- paid walk-in member creation and its exact manual membership revenue row without a fabricated player ID;
- request approval with no revenue and the established targeted notification;
- approved-member activation with membership dates, price-label parsing, authoritative player identity, revenue, and notification persistence.

The expanded unchanged-production boundary passed 3 files / 15 tests before extraction.

## Implementation

- Added `src/application/management/profileCommands.ts` for quick profile construction, active walk-in creation, edit normalization and reference-name propagation, deletion, selected duplicate merges, and canonical club check-in/removal.
- Added `src/application/management/membershipCommands.ts` for request approval, in-person activation, membership windows, notification pruning, validation outcomes, and optional manual revenue.
- Injected identity and clock dependencies. Neither module imports React, browser, Electron, Firebase, or storage APIs, and neither contains explicit `any`.
- Kept form/draft state, confirmation, membership-QR validation, demand prompting, UI feedback, usage descriptors, persistence, and route composition in `App`.
- Preserved authoritative-ID precedence, unique-unlinked-name fallback, ambiguous/no-match behavior, selected-reference rewrites, source order, membership statuses/dates, price parsing, revenue categories/amounts/order, notification order/expiry, and the no-fabrication rule for walk-in revenue.
- Added 11 direct command cases. The renderer suites retain orchestration/persistence characterization while the direct suites own the pure transitions and explicit failures.

`src/main.tsx` decreased from 4,700 to 4,446 lines. Its `App` function decreased from 4,068 to 3,804 lines. The focused profile and membership modules are 357 and 137 lines.
