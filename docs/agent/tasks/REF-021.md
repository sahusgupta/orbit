# REF-021: Extract canonical Player discovery selectors and view models

Status: `complete`

Date: 2026-08-08

## Objective

Move platform-independent Player screen/filter/opportunity contracts, discovery filtering and ordering, distance/location rules, grouping and player-facing discovery labels, form validation, and immutable game-preference updates out of `PlayerApp.tsx` into directly tested modules that a future web presentation can consume without React Native or Expo.

## Characterization gate

The existing Player domain baseline passed 4 files / 20 tests and Player TypeScript before production work.

Commit `c673010` then introduced a temporary named seam inside the unchanged `PlayerApp.tsx` owner and added eight dense fixtures. They pin:

- address keyword resolution, home fallback, deterministic club coordinates, and 3,958.8-mile-radius haversine distance;
- private-game query/stakes/type filtering and input immutability;
- map query, venue, distance, and nearest-first selection;
- tournament search fields, club/distance/status/free/registered filters, missing-club behavior, and start ordering;
- game opportunity eligibility, casino/non-casino gates, active-request exclusion, query/stakes/type/distance behavior, and activity/favorite/fit/distance sorting;
- saved/pass deck projection and active-card refresh by stable club/game key;
- opportunity, compatibility, status, venue, city, table, grouping, and recommendation labels;
- email/phone validation and immutable preferred-game toggling.

The fixtures captured two non-obvious current behaviors before extraction: Bryan-to-Dallas resolves to 152.230 miles with the configured address points, and tournament query matching includes prize-pool/rules text. The temporary seam passed 5 files / 28 tests and Player TypeScript before any owner moved.

## Implemented ownership

- `player-app/src/domain/playerTypes.ts` is the canonical platform-neutral owner for Player screen/navigation identifiers, discovery/tournament/map filter unions, access/decision unions, coordinates, seat-request drafts, game/tournament opportunities, and private-game drafts.
- `player-app/src/domain/discovery.ts` owns the characterized private-game, map, tournament, and live-game selectors; decision projections; location/distance rules; active-game and activity-time selection; stable keys; discovery grouping; game/venue/city/table/recommendation labels; email/phone validation; and immutable preferred-game toggling.
- `PlayerApp.tsx` imports those contracts and selectors. Its `useMemo` calls retain their exact dependency arrays and invoke the pure owners; React state setters wrap the immutable toggle helper.
- `discovery.test.ts` now imports the pure domain module directly. All React Native, Expo, native-map, storage, Firebase, and purchase mocks used by the temporary seam were removed.

Club membership/checkout fee labels, in-app notification selection, native map presentation, navigation effects, React state, network/Firebase behavior, storage, purchases, and all React Native components/styles remain platform-specific and were not broadened into this task.

## Player-web readiness

The two new modules have no React, React Native, Expo, native-map, storage, network, Firebase, or purchase imports. A future web presentation can reuse their types and pure functions directly from source. Platform-specific rendering and adapters remain outside this reusable boundary and are explicitly not claimed as web-ready.
