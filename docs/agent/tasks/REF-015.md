# REF-015: Extract table planning and lifecycle commands

Status: `complete`

Date: 2026-08-08

## Objective

Move forming, demand-driven, planned, and balanced table creation; game switching; selected-player starts; table patches and timestamp corrections; and lifecycle events out of `src/main.tsx` into focused pure application commands without changing IDs, clocks, participant ordering, seats, events, manual edits, audit records, feedback, telemetry, usage, or persistence behavior.

## Characterization

Before production edits, the existing table-planning, planned-participant, and lifecycle suites passed 3 files / 19 tests.

Two missing unchanged-production boundaries were added and committed separately as `aca78c3`:

- forming-table start with selected players in source-interest order, including seating, event text, usage metadata, persistence, and draft reset;
- demand-prompt game switching, including exact table/player collection propagation, manual-edit timestamps, event content, and persistence.

The expanded unchanged-production boundary passed 4 files / 27 tests before extraction.

## Implementation

- Added `src/application/management/tableCommands.ts` for normal and demand-driven forming tables, planned and balanced tables, running-table game switches, and selected-player table starts.
- Added `src/application/management/tableLifecycleCommands.ts` for table patches, timestamp corrections and audit records, and started/failed/broke/closed lifecycle propagation.
- Injected ID and ISO-clock dependencies and reused the pure seating boundary. Neither module imports React, browser, Electron, Firebase, or storage APIs, and neither contains explicit `any`.
- Kept drafts, dialogs, notifications, save feedback, telemetry, usage descriptors, persistence, and route composition in `App`.
- Preserved ID/clock call order, collection defaults, source-interest and participant order, planned IDs, table labels, seat counts/caps, event order/content, manual edits, correction-log capping, player/dealer closure, and failure behavior.
- Added 12 direct command cases. The renderer matrices remain as orchestration/persistence characterization while the direct suites own the pure transitions.

`src/main.tsx` decreased from 4,991 to 4,700 lines. Its `App` function decreased from 4,370 to 4,068 lines. The focused planning and lifecycle modules are 373 and 143 lines.
