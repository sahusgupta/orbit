# REF-022: Split Player presentation by feature

Status: `complete`

Date: 2026-08-09

## Objective

Move cohesive Player screens, presentation helpers, and feature-owned React Native styles out of `PlayerApp.tsx` one characterized feature at a time without changing native/web component hierarchy, copy, accessibility properties, callback wiring, animation values, platform behavior, or style values.

## Characterization gate

REF-022 started from the green REF-021 boundary: 73 files / 401 tests, Player TypeScript, all root compiler projects, and the 1,956-module management build.

`src/lib/playerOnboardingPresentation.test.ts` was added before the first move and expanded before every later feature move. Its final 12 cases locate each presentation function and style by owner, normalize only line endings, and pin:

- onboarding hierarchy, step components, shared form/map primitives, callbacks, animation implementation, and 55 style values;
- discovery search/filter/map/detail/hosting/list/deck components and 281 style values;
- tournament screen/card/filter composition and 39 style values;
- club, plan, checkout, wallet, QR, seat-request, and hub components plus 123 feature/shared style values;
- settings hierarchy and ordered account, identity, premium, preference, support/legal, sign-out, and deletion actions;
- identity verification, in-app notification, screen-title, identity-label, and notification-selection implementations plus 37 feature/shared style values;
- the final `PlayerApp` navigation-shell style inventory and the absence of unreferenced local style declarations.

Player TypeScript passed before and after every feature move. No native package build or remote EAS workflow was invoked.

## Implemented ownership

| Concern | Presentation/style owner |
| --- | --- |
| Onboarding flow and step screens | `player-app/src/features/onboarding/OnboardingScreen.tsx` and `onboardingStyles.ts` |
| Shared Player fields and location picker | `player-app/src/components/PlayerFields.tsx` and `MapPicker.tsx` |
| Discovery deck, filters, details, hosting, lists, and map | focused files under `player-app/src/features/discovery/` with `discoveryStyles.ts` |
| Tournament screen, cards, dates, and filters | `player-app/src/features/tournaments/TournamentScreen.tsx` and `tournamentStyles.ts` |
| Club route/store/seat-request presentation | `player-app/src/features/clubs/ClubRoutes.tsx` |
| Club hub, membership panels, games, and history | `player-app/src/features/clubs/ClubHub.tsx` |
| Membership application, wallet, and QR presentation | `player-app/src/features/clubs/MembershipWallet.tsx` |
| Club-owned styles | `player-app/src/features/clubs/clubStyles.ts` |
| Profile/account/preferences/settings | `player-app/src/features/settings/SettingsScreen.tsx` and `settingsStyles.ts` |
| Identity verification | `player-app/src/features/settings/IdentityVerificationScreen.tsx` |
| In-app notification popup and styles | `player-app/src/components/InAppNotificationPopup.tsx` and `player-app/src/styles/notificationStyles.ts` |
| Pure current-notification selection | `player-app/src/domain/playerNotifications.ts` |
| Shared animated surfaces/buttons/menu rows and shared style values | `player-app/src/components/PlayerPresentation.tsx` and `player-app/src/styles/sharedStyles.ts` |
| Navigation, state/effects, use-case callbacks, route assembly, sheets/modals, and 15 referenced shell styles | `player-app/src/PlayerApp.tsx` |

The remaining `PlayerApp` owner is intentionally cohesive for REF-023 rather than a presentation backlog: it owns application state, storage migration, subscription/effect lifecycle, purchase/authentication/network use cases, navigation, and composition. It contains no colocated feature screen/helper component and only the 15 shell styles referenced by its own header/content/tab layout.
