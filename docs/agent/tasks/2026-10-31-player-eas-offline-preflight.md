# Offline Player EAS build preflight — October 31, 2026

This focused continuation adds a read-only preflight to reduce avoidable build attempts while EAS capacity is uncertain. It changes no application behavior, dependencies, production profile, signing settings or submission guard. Scope is the [preflight](../../../scripts/player-build-preflight.mjs), its [tests](../../../scripts/player-build-preflight.test.js), the root npm command and [operator instructions](../../../player-app/README.md).

## Boundary and behavior

Run from the repository root: `npm run player:build:preflight -- --source-sha <40_CHAR_REVIEWED_SHA>`.

The command reads only selected local Git state, authored public configuration, installed EAS package metadata and the resolved iOS production profile through the existing locked EAS schema. It uses the existing production environment validator. The full release-contract check remains authoritative and is not replaced. It never executes EAS, authenticates, reads credential/environment files, contacts a provider, builds or submits.

Local checks require an exact case-insensitive SHA match, a clean checkout on a branch other than main, the locked CLI version and selected resolved production store/device profile invariants and the existing commit/remote-increment policy. Detached HEAD is unknown and blocked. Git operations have a ten-second deadline and 64 KiB output bound; their environment contains only selected OS path/temp values and fixed Git controls, with global/system config disabled and filesystem monitoring disabled. Dirty filenames and raw Git errors are not reported.

Optional `--usage-json-stdin --observed-at <UTC_ISO_TIMESTAMP>` accepts the JSON shape emitted by the repository-pinned EAS 23.2.0 `account:usage` command. Input is bounded to 64 KiB and five seconds and is not consumed without that explicit flag. Validation uses the configured public owner, strictly supported Free-plan accounting, safe integer total/iOS counts, valid UTC dates, a maximum 15-minute observation age and a reported billing cycle containing both observation and current time. Both allowances must have capacity; stale observations never establish a reset at calendar rollover. Paid/unknown plans require separate billing review.

Only fixed status codes, counts, canonical dates, the source SHA and booleans leave the tool. Account names, unknown metadata, URLs, invoices, credentials, input/error text and environment values are omitted. Git and explicit stdin work have finite bounds; failures return a static redacted message or fixed blocker code. This is supplied evidence, not authenticated provider freshness: `usageObservationSource` says `supplied-json-not-authenticated`. Exit 0 means only local and supplied-capacity checks passed. `readyToBuild` is always false; fresh exact-source CI, source-archive review, live account/project, Apple signing and explicit build confirmation remain external gates.

EAS build allowance and Firestore gRPC `RESOURCE_EXHAUSTED` are distinct. No generic quota/error-text classifier was introduced. Existing exact-build TestFlight submission verification remains unchanged and cannot select latest implicitly. Local iOS compilation still requires a Mac/Xcode; this Windows preflight supplies no signed IPA or physical-device evidence.
