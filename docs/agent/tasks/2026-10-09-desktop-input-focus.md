# Desktop input and modal focus regression

Scope: repair renderer modal focus ownership and verify actual keyboard editing in Floor workflows. Baseline checkout: `16b9161` (documentation following verified stable source `12f66e0da803fffea4bc8b1d16e28f4a655bcbdc`, release `v0.1.78`). The durable mutation fix `fb7c824924a210c362046b4679ae66991ecf149a` is an ancestor and remains intact. Work is on `fix/desktop-modal-input-focus`; no API contract, persisted shape, sync protocol, authentication, or datastore change is included.

## Reproduction and root causes

Before integrating the product change, the isolated focus smoke reproduced the seat picker failure in Chromium and Electron. Pointerdown targeted the picker input outside `.floor-workspace-popup`. Focus left the Current Tables Add Player button, but Radix immediately restored that same button. Click and the following animation frame still showed the button as `document.activeElement`; the input never acquired usable keyboard focus. Diagnostics record only element tag/id/role/class and focus-scope containment, never field values.

The recorded order was `pointerdown(INPUT in seat picker, outside workspace/Radix Content)` -> `focusout(Current Tables Add Player BUTTON)` -> `focus/focusin(same BUTTON restored by the parent scope)` -> `click(INPUT, activeElement still BUTTON)` -> `animation-frame(activeElement still BUTTON)`. With the button still active, native typing cannot edit the picker or reach its `onChange`.

Current Tables remains a modal Radix dialog while the picker, cash-out, or ledger is open. The former `createPortal(..., document.body)` children were physical DOM siblings of its Content, and created no child FocusScope/DismissableLayer. Installed Radix restores its last focused descendant on outside focusin/focusout; it pauses that parent only when a real child scope mounts. The CSS z-index and pointer-events overrides did not establish focus ownership. The ledger reproduced the same defect.

The embedded Add Time/Deduct Time route has separate obstacles: production CSS hid the entire `.table-detail-panel`, so the embedded table could not be clicked through accessible locators. Its details trigger also bubbled to the enclosing card's Table View navigation handler. PlayerCard's controlled draft state, stable player keys, and one-second clock updates showed no evidence of an input-model defect. Dealer, hand-count, and break-note fields passed real keyboard/timer checks against the unchanged source.

The global command dialog used z-index 100/101 beneath Current Tables at 150/151, so the workspace backdrop intercepted pointer selection. Choosing Add player interest also retained the previous workspace's focus trap while opening the custom Quick Add drawer outside it. Dedicated cash-out inputs could be edited, but Tab escaped that custom modal because it had no focus scope of its own.

The v0.1.78 mutation smoke clicked an existing candidate without typing, closed Current Tables, and used `.fill()` only in dedicated Table View. It did not assert activeElement, native keyboard input, or the embedded Floor flow.

## Architecture and implementation

- [OperationalDialog](../../../src/components/OperationalDialog.tsx) registers the seat picker, cash-out form, ledger, and Quick Add with Radix Root/Portal/Overlay/Content. The parent is paused while the child owns focus. Initial search/amount/name focus occurs once in `onOpenAutoFocus`; Tab/Shift+Tab remain in the child; Escape closes only the top dialog. Close restores the initiating control. Existing outside-click non-dismissal is preserved for the three table modals; Quick Add retains outside dismissal.
- [main.tsx](../../../src/main.tsx) uses that helper for all three formerly custom body portals, preserves dialog labels, and gives search an explicit accessible label. Cash-out captures the same table's persistent seat marker as a fallback when successful removal disconnects the original player trigger. The Quick Add command captures its underlying dialog as the return target before the command palette unmounts.
- [FloorView](../../../src/components/FloorView.tsx) keeps embedded clicks within the table detail surface and lets Escape dismiss player details before the workspace. Quick Add participates in the same modal stack, including when opened from component-local Floor utilities or room-map dialogs, and preserves the underlying workflow/draft state. [PokerTable](../../../src/components/PokerTable.tsx) ignores Escape owned by another active dialog and transfers cash-out focus to its stable seat trigger before the transient menu unmounts.
- [Floor CSS](../../../src/styles/141-table-floor-operations.css) restores the existing embedded controls. [Shell CSS](../../../src/styles/180-app-shell.css) places the global command dialog above workspace/operational overlays. [floorWorkspace](../../../src/features/floor/floorWorkspace.ts) honors an already-handled Escape.
- [AppShell](../../../src/components/AppShell.tsx) captures the keyboard/pointer command opener and restores it in the close lifecycle. Its command dialog has no Radix Trigger, so Radix's default trigger restoration alone could not return to the underlying text draft. The expanded Electron test reproduced command-input focusout leaving `BODY` after Escape while Quick Add stayed open. After focus restoration was added, continued native typing exposed a retained select-all range from the parent's rejected opening focus attempt. AppShell now captures and restores text-input/textarea selection start/end/direction before opening and after closing; numeric/date inputs with no selection range are left native.

Repeatedly selecting Add player interest while Quick Add was already open exposed another restoration edge: capturing the current dialog again selected Quick Add itself, which disconnected on close. The native Activity case reproduced focus remaining on `BODY`. The command now records its return target only when opening a closed drawer, retaining the original underlying workspace or stable Floor control on repeated selection.

The remaining custom body portals are the base Floor room-map/classic context menus. Their openers are outside Radix workspaces; they do not share the trapped-dialog ownership defect. Global ordinary-letter/number/backspace/arrow handling remains native; the command shortcut requires Ctrl/Meta+K.

## Regression coverage and isolated execution

[Component tests](../../../src/components/OperationalDialog.test.tsx) cover nested and standalone focus, stable input nodes, parent-focus rejection, boundary Tab looping, top-only Escape, restoration/fallback, and outside dismissal policy. [PokerTable tests](../../../src/components/PokerTable.test.tsx) cover the cash-out handoff, Add/Deduct draft retention through clock/parent renders, native ordinary keys, and an actual parent/child Radix Escape stack. Actual user keyboard input is covered by [the focus smoke](../../../tests/e2e/management-focus-smoke.mjs), not jsdom value injection.

[AppShell tests](../../../src/components/AppShell.test.tsx) exercise keyboard/pointer command openers, Escape restoration with exact selection ranges, retained controlled draft/node identity, and unmodified letters/numbers/Backspace/arrows. [Floor callback coverage](../../../src/components/FloorCollectionCallbacks.test.tsx) also verifies that Escape closes embedded player details while Current Tables stays open and returns focus to the same seat trigger before continuing cash-out. The new focus coverage adds twelve unit cases in total.

Run `npm run e2e:management:focus` for Electron, or `node scripts/run-management-focus-smoke.mjs --browser` for Chromium. [The runner](../../../scripts/run-management-focus-smoke.mjs) uses the existing production Vite configuration with `envDir: false`, an allowlisted environment, synthetic authentication, disabled Electron/renderer Firebase sync, disabled embedded backend, unique temporary user data, and a [memory-only API fixture](../../../tests/e2e/fixtures/management-focus-api.mjs). It refuses occupied local ports 4185/5173 and blocks external renderer requests. No developer dotenv file, production credential, private key, or hosted service is required.

The optional `--reuse-build` mode requires the isolation receipt written only after this runner's successful fresh build. Ordinary Vite builds clear that receipt. A negative check against an ordinary build exited 1 before launching services, as required; runtime environment flags alone cannot make a prebuilt production bundle isolated.

The new command is required by [CI](../../../.github/workflows/ci.yml), [release](../../../.github/workflows/release.yml), and [release-control verification](../../../scripts/verify-release-controls.mjs). The existing authoritative mutation smoke remains a separate gate.
