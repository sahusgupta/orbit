# REF-003: Extract report windows and financial analytics

Status: `complete`

Date: 2026-08-07

## Objective

Move report-window projection, collection/revenue summaries, table/player financial summaries, hourly buckets, and dealer reporting from `src/main.tsx` into a pure focused module without changing calculations, interval semantics, ordering, or input state.

## In scope

- local date parsing/formatting used by report windows;
- report window creation, shifting, and half-open timestamp membership;
- report-state clipping/filtering;
- collection-profile lookup used by financial calculations and existing callers;
- report/table/player financial projections;
- hourly and dealer projections.

Rendering, report submission, analytical payload shape, persisted data, and any financial-rule redesign remain out of scope.

## Characterization

Before relocation, `src/domain/reporting.test.ts` imports the unchanged implementation through a temporary named test seam in `main.tsx`. Its three cases pin:

- local day/week boundaries, half-open membership, invalid timestamps, and anchor shifting;
- exact-versus-legacy time-fee precedence, canonical revenue categories including `time-package`/refund, table/player totals, hourly order, and state immutability;
- overlapping session/player clipping, timestamped collection filtering, and ordered dealer hours/hands/rates.

The pre-change focused command passed 1 file/3 tests.

## Acceptance criteria

- The three direct cases remain exact after importing the focused module.
- `src/main.tsx` no longer owns these projection implementations or a test-only export seam.
- No domain value, financial category, payload, ordering rule, or input state changes.
- Focused tests and `npm run verify` pass.

## Implementation and verification

- Added `src/domain/reporting.ts` as the focused owner of report windows, report-state projection, collection-profile lookup, financial summaries, hourly buckets, and dealer summaries.
- Replaced the implementations and temporary test-only exports in `src/main.tsx` with direct imports. The existing local-date formatter remains in the entrypoint because the UI also uses it to identify the current reporting period.
- Rewired `src/domain/reporting.test.ts` to import the pure module directly, removing the renderer mount and Firebase mocks.
- Focused reporting and table-event reporting passed 2 files/5 tests; both root compiler projects passed with zero diagnostics; Player TypeScript, all 36 files/192 tests, the 1,915-module renderer build, and `npm run verify` passed.
- `src/main.tsx` decreased from 9,364 to 9,072 lines. No calculation, category, interval, ordering, persisted shape, external service, or deployment changed.
