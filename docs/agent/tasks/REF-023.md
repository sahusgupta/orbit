# REF-023: Extract Player application and storage orchestration

Status: `complete`

Date: 2026-08-09

## Objective

Move Player account storage/migration, dismissed-alert persistence, native platform services, identity and premium lifecycles, profile/live-data subscriptions, and feature workflows out of `PlayerApp.tsx` without changing storage keys, authentication restore, foreground refresh, user messages, request construction, navigation behavior, or transport contracts.

## Characterization gate

`src/lib/playerApplicationOrchestration.test.ts` was added against unchanged production source and committed separately as `37f9c42`. It pinned the complete account-storage effects and local reset/dismiss actions plus the eight authentication, identity, premium, profile, live-club, private-game, and tournament lifecycle effects. The pre-change gate passed 1 file / 2 tests and Player TypeScript before production moved.

REF-024's 3-file / 44-test fake-only external-data and subscription boundary was already complete. No Firebase SDK, HTTP socket, hosted endpoint, credential, database, or production record was contacted.

Application hooks import React and domain/data contracts but no React Native module. Native confirmation, app-state, browser, directions, and platform selection enter through the `playerPlatform` adapter. AsyncStorage is imported only by `playerStorage.ts`.

## Preserved behavior

- Account reads keep exact priority: `orbit-player-account-v1`, then `tabletalk-player-account-v1`, then `tabletalk-player-account-v2`.
- Missing/malformed/invalid accounts still leave onboarding un-restored and finish the load; restored accounts still require trimmed name/email and normalize invalid preference/favorite collections to empty arrays.
- Account writes still require a loaded, active account with non-empty name/email. Dismissed alerts retain their key, unique-ID append behavior, and persisted JSON shape. Local reset still clears current and legacy account keys.
- Firebase auth listener ownership, identity reset, immediate identity refresh, active-app forced-token refresh, messages, verification browser flow, connection mapping, recent-login deletion message, and sign-out ordering are unchanged.
- Premium remains feature-flagged and account/player gated; iOS availability, configuration, offering, purchase/restore messages, change listener, and cleanup are unchanged.
- Live clubs still refresh immediately, poll only while active, stop in the background, refresh once on a background-to-active transition, restart polling on active events, and detach app-state plus data listeners on cleanup.
- Profile merge, membership-status transition messages/navigation, private-game and tournament subscriptions, request construction, configured-sync fallbacks, optimistic local updates, and all user-visible workflow messages moved without contract changes.
- `orbitSyncApi.ts`, Firestore/API paths and schemas, protocol-v2 selection, and legacy fallback logic were not changed.
