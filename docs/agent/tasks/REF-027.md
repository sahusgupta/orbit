# REF-027: Consolidate API privileged client bootstrap

Status: `complete`

Date: 2026-08-10

## Objective

Give Firebase Admin app/credential bootstrap and Stripe client construction one API-internal owner each while preserving credential precedence, provider initialization, service exports, routes, errors/statuses, authorization, webhook verification, idempotency, and per-club isolation.

## Characterization gate

Commit `2a7dc49` added unchanged-production characterization for the three duplicated service bootstraps. The gate recorded:

- Firebase service-account JSON precedes base64 in identity, license, and payment services;
- only the license service explicitly parses `GOOGLE_APPLICATION_CREDENTIALS`, while other Firebase Admin callers retain SDK default discovery;
- an existing Firebase Admin app is reused before credential parsing and initialization occurs at most once per service owner;
- the exact missing-Stripe-key error is raised before client construction; and
- identity and payment cache their Stripe clients.

The unchanged-production characterization passed 13 tests. Its environment, file, Firebase Admin, and Stripe dependencies were injected fakes with placeholder values; no provider SDK call, credential file, secret, network, or production service was used.

## Implemented ownership

`apps/api/src/services/firebaseAdmin.js` now owns lazy Firebase Admin SDK loading, JSON/base64/opt-in-file credential parsing, existing-app reuse, and a single cached Admin app. Its factory seam accepts environment, SDK-loader, and file-reader dependencies for isolated tests.

`apps/api/src/services/stripeClient.js` now owns lazy Stripe constructor loading, the unchanged missing-key error, and a single cached Stripe client. Its factory seam accepts environment and constructor-loader dependencies.

`identityService.js`, `licenseService.js`, and `paymentService.js` consume these owners. The license call opts into explicit credential-file parsing; identity and payment do not. Their exported handlers, route registration, request/response shapes, Firestore paths, transaction ordering, webhook verification, and payment/identity rules are unchanged.

`firebasePublisher.js` remains the deliberately separate Firestore REST publisher, and `cleanupStressClubs.js` remains an explicit administrative script. Neither constructs the runtime services' Firebase Admin app or Stripe client, so neither belongs to this service-bootstrap owner.

## Security review

- Tests use only local placeholder strings and injected fakes. They neither read the process credential path nor load Firebase Admin or Stripe.
- Production credential values are neither logged nor returned. Precedence remains JSON, then base64, then the license-only explicit credential file.
- Existing Admin apps short-circuit credential parsing. A fresh app and the Stripe client are each constructed once per shared runtime provider.
- Missing credentials retain their prior behavior: Stripe raises `STRIPE_SECRET_KEY is not configured.`; Firebase Admin initializes without an explicit credential so its established default discovery remains available.
- No route, authorization boundary, webhook token/signature check, document path, provider version, dependency, idempotency key, or per-club scope changed.
