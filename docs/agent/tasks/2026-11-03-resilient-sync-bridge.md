Original milestone: November 3, 2026, branch `codex/resilient-management-sync`. ## Scope and behavior

The original renderer and IPC reject normal actions when retained operational data crosses 2,000,000 UTF-8 bytes, before backend chunk storage can help. Characterization reproduced this with actual request envelopes and multibyte retained ledger/profile data. The embedded backend was inspected: its limit applies to analytical reports; it has no management-state authority.

The bridge negotiates `checkpoint-v1`, transfers bounded resumable chunks, retains tenant/revision/idempotency identity, preserves history, and finalizes through the existing atomic Firestore state/receipt/outbox transaction. Identity, checksums, expiry, idle takeover, source/compressed/envelope budgets and bounded cleanup prevent partial authority or unlimited staging. Legacy whole-state requests remain bounded. Legacy server-field/privacy preservation now also runs inside the transaction.

Desktop pending snapshot+identity+revision+transport are durably OS-encrypted before sending; retries and restart retain them. Browser operational pending data uses protected transactional IndexedDB, omits restricted credentials and verifies its original source when rehydrating. Credential changes and legacy credential-derived account identities use online-only transient transfer, with no false durable-queue claim. Pending projections remain provisional. Wrong tenant/operation/revision acknowledgements cannot clear them. Complete canonical polling replaces the old partial merge that could overwrite omitted authoritative fields.

See [protocol, resource budgets, offline matrix and measured evidence](../../architecture/RESILIENT_MANAGEMENT_SYNC.md) and the [server-first upgrade/recovery/rollback runbook](../../operations/RESILIENT_SYNC_UPGRADE.md). New Firestore TTL/index JSON is an undeployed input.

## Remaining completion gates

This bridge still materializes/replaces bounded full state and globally conflicts. It permits one unresolved snapshot per tenant and deliberately blocks incompatible work. Changed-revision recovery still has documented repeated decompression/read costs. Production versions, venue sizes, growth correlation, real Firestore/provider performance, deployed TTL, adoption and actual rollout remain unverified.

The next milestone must introduce bounded domain commands, transactional command/projection queues, per-command preconditions/conflict resolution, independent replay, durable ordered change feed/cursor recovery, protocol gates, history/query normalization where needed and recovery/export. Extend the validated command workflow to every mutation path before declaring whole-state saves retired. Do not publish this partial migration as the completed reliability redesign.
